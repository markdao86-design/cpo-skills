# 评估标准
什么时候读我：评测阶段，或者选skill市场里的skill。

## 一、好skill七条(上线门槛)
1. 叫得醒：五个真实问题至少四次触发。
2. 有判断：写了"什么情况下用哪个、什么情况下不用"。
3. 有反例：至少四条常见误用。
4. 讲为什么：每条硬规则带原因，无全大写MUST。
5. 分层加载：主文件五百行内，参考按需。
6. 输出有形状：固定章节/模板/样例，拿到能直接用。
7. 锚业务：知道用户是谁、站什么立场、落到钱上。

## 二、标准化任务评估(有唯一对错)
写assertion，自动判：
```json
{"text": "输出包含滩头评分表且有九列", "check": "regex或脚本"}
```
原则：assertion名要一眼看懂在查什么；能用脚本查的别用眼看；有无skill都通过的是废assertion，删。
指标：通过率、耗时、token。with-skill要比无skill通过率高且token不失控。

## 三、非标准化任务评估(律师写协议类)
没有唯一答案，用专业度评分卡，人看打分，每项一到五分：

| 维度 | 问什么 |
|---|---|
| 判断正确 | 结论是不是专家会给的那个 |
| 取舍明确 | 有没有说不做什么、什么情况下掉头 |
| 证据充分 | 每个判断有没有依据或假设 |
| 落地可用 | 能不能直接发给同事或客户 |
| 业务贴合 | 有没有用对立场和口径 |

总分二十以上算专业。评分卡先于skill写好，否则做完没法比。
盲比法：两个版本输出去掉标记给第三方判优劣，再分析赢在哪。

## 四、skill市场选型(装别人的skill)
三红线任一不过直接淘汰：许可证不能商用 / 带可疑脚本或外发数据 / 九十天无提交。
五维各一到五分：触发准度(30%) / 方法密度(30%) / 输出可用度(15%) / 上下文成本(12%) / 可改造度(13%)。
星数只当入场券。

## 五、评测集写法
三到五条种子问题，要像真人说的：带文件路径、公司名、背景、口语、错字。
应触发和不应触发各写一半，不应触发的要是"近似但不该"的，不要写明显无关的。
